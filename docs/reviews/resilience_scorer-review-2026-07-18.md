# resilience_scorer — architecture & code review (2026-07-18)

**Scope:** full-module review, input → app → domain → developer → infrastructure, with refactors applied in-tree (uncommitted).
**Relation to prior cycle:** builds on `docs/reviews/resilience_scorer-review-plan.md` (commits `b1b314d…ed5f181` + retry follow-up `0c1fd7e`), which already resolved dead code, most duplication, indirection collapse, config consolidation (sqlitePath/envFlags/modelIds), CLI error-handling standardization, and the oversized `assessSignalsCli`/`componentDiagnostics`/`signalTypeHygiene` splits. Every finding below was re-verified against source on this date; findings the prior cycle already adjudicated are not re-raised.

## 1. How the module works

```
input/run-pipeline.js
  └─ app/pipeline/pipelineOrchestrator.js  (preset → buildPipelineIngestPlan → spawns child CLIs per source)
       ├─ input/extract-signals.js → app/extraction/extractSignalsCli.js → extractionStage.js
       │     ├─ closedCatalogueExtractService → infrastructure/claudeEvaluator (Haiku) → signals-{src}-{date}.json
       │     └─ openVocabularyExtractService → open_observation_extraction (parallel open observations)
       └─ input/assess-signals.js → app/assessment/assessSignalsCli.js
             ├─ assessSignalsDeps.loadPreparedSignals   (bundle discovery/merge/dedup/geo/probes)
             ├─ buildScopedScoring                      (per-source + national /10 via app/scoringFacade → developer/)
             ├─ assessmentStage.runPostExtractionAssessmentCore
             │     ├─ signalScopePartition → prepareSignals → scoringPipelinePrep (epistemic gate, EWMA)
             │     ├─ produceAssessmentWithShadow (agent v2 + degrade ladder)  OR  closedCoreNarrate (score shell)
             │     ├─ userNarrativePipeline  (RAG → facts → judge → polish → validate; Sonnet)
             │     └─ omissionAuditService → attachDecisionBrief
             └─ finalizeReport.finalizeAndWriteReport → infrastructure/reportWriter (.md/-brief.md/.json) → domain event
Server twin (in-process, DI-clean): app/resilienceAnalysisService.runResilienceAssessment
Serving: input/reportRoutes.js (Fastify) → index.js facade → reportCacheService / redaction
```

Layer inventory: `input/` 9 entrypoints; `app/` ~35 (pipeline 5, extraction 7, assessment 21, user, catalog, 3 root); `domain/` ~140 (contracts 25, epistemic 13, ports 7, services 87 in 11 subdirs, value_objects 2); `developer/` 11 (quarantined /10 scoring engine, sole bridge `app/scoringFacade.js`, dependency-cruiser-enforced); `infrastructure/` 11 adapters + ~26 root files.
