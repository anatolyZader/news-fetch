## Your task

`/x-3 <topic>` runs a dry-run-first, cost-disciplined, citizen-voice X search pipeline for the last 3 days focused on northern Israel. The topic vocabulary is constructed at runtime from the user's string. Output is written to topic-slug-suffixed files so multiple `/x-3` runs on different topics coexist on the same day, and never collide with the canonical bundle written by `/x-3-full`.

**You spend real money on TWO meters: X API credits AND Claude API tokens.** The cost-discipline rules below are mandatory.

---

## Arguments

Parse `$ARGUMENTS` as a mix of flags and remaining tokens. Everything that isn't a flag (and isn't a `dd:mm:yyyy` date) joins back into the topic string in original order.

- `<topic>` (required) — free-text topic in any language. Examples: `power outages`, `מקלטים בצפון`, `evacuation centers`, `школьники`.
- `--execute` — perform paid `search/recent` calls. Absent → dry-run only.
- `--with-replies` — fetch replies per citizen-candidate. Implies `--execute`.
- `--max-per-query N` — cap posts per (date × language) call. Default `50`, hard ceiling `100`.
- `--max-cost-usd X` — pre-flight abort threshold for **X API** spend. Default `2.00` (kept low because topic volume is unknown until the dry-run completes).
- `--broad` — drop the north-Israel locality AND-clause. Use only when the topic itself implies the region (e.g. `/x-3 פיקוד צפון --broad`).
- `--lang LIST` — comma list from `{he,ar,ru,en}`. Default `he,ar,ru`.
- Optional date `dd:mm:yyyy` — anchor for the 3-day window. Absent → today (Asia/Jerusalem). Future date → abort.

If `<topic>` is empty → abort with: `Usage: /x-3 <topic> [--execute] [--with-replies] [--max-per-query N] [--max-cost-usd X] [--broad] [--lang he,ar,ru]`.

## Cost discipline (READ BEFORE ANY STEP)

Apply these rules:

1. **Never `Read` a raw X JSON file.** Pipe through `jq`; only ingest slim summaries.
2. **Slim candidate file is the single source of truth for classification.** Build `x-candidates-<target>-<slug>.jsonl` once, read THAT file only.
3. **Hard cap on classification batch: 60 candidates per 3-day run total.** Drop overflow into `rejected.off_topic`.
4. **No exploratory re-reads.**
5. **Use bash counters and `wc -l`, not `Read`, to count lines.**
6. **Per Bash invocation, output ≤200 lines.** Pipe big output to file, `head`/`tail` only the summary.
7. **Skip work entirely in dry-run.** No `search/recent`, no pre-filter, no classification, no bundle writes. Only Step 0 (build queries) and Step 1 (`counts/recent`).
8. **No agent spawning.** Single-pass, single-context.

### Target spend per 3-day run

| Meter | Dry-run | --execute | --execute --with-replies |
|---|---|---|---|
| X API | ≤$0.05 | ≤$2 | ≤$5 |
| Claude API | ≤$0.05 | ≤$1 | ≤$2 |

The dry-run estimate is the only signal of topic volume — rerun with a higher `--max-cost-usd` if needed.

## Pre-flight

**P1.** Token:
```
test -n "$X_BEARER_TOKEN" || {
  LINE=$(grep -E '^X_BEARER_TOKEN=' .env | head -1)
  VAL=${LINE#X_BEARER_TOKEN=}; VAL=${VAL%\"}; VAL=${VAL#\"}; VAL=${VAL%\'}; VAL=${VAL#\'}
  export X_BEARER_TOKEN="$VAL"
}
test -n "$X_BEARER_TOKEN" || { echo "X_BEARER_TOKEN is not set. Aborting before any spend."; exit 1; }
```

**P2.** `mkdir -p business_modules/social_media/data`.

**P3.** Compute the 3 UTC dates (target, target-1, target-2) from the date arg or `TZ=Asia/Jerusalem date +%F`. Same `YYYY-MM-DD` form everywhere.

**P4.** Derive a filesystem-safe slug from the topic:
```
SLUG=$(printf '%s' "$TOPIC" | tr '[:upper:]' '[:lower:]' | tr -c '[:alnum:]' '-' | sed 's/^-*//; s/-*$//; s/--*/-/g' | cut -c1-32)
[ -z "$SLUG" ] && SLUG="topic-$(printf '%s' "$TOPIC" | md5sum | head -c 8)"
```
Non-ASCII topics collapse to `-` then fall back to an md5-prefixed slug. Filenames stay portable.

**P5.** Spend log: `business_modules/social_media/data/x-spend-log-<target>-<slug>.jsonl`. Never write the bearer token there.

## Step 0 — Build per-language queries from the topic

For each language in `--lang`, you (Claude) construct a query string ≤512 chars:

```
(<topic_terms_in_lang>) (<locality_in_lang>) lang:<code> -is:retweet
```

**Topic terms** — translate/synonymize `<topic>` for the language. 3–8 OR-joined terms; include verbatim user tokens when the language matches; quote multi-word phrases. Aim for common civilian vocabulary, not officialese.

**Locality (omit if `--broad`):**
- **he**: `(קריית שמונה OR נהריה OR צפת OR מטולה OR שלומי OR חיפה OR גליל OR גולן OR "ראש פינה" OR מעלות OR חורפיש OR מרגליות OR יראון OR אביבים OR "קריית ביאליק" OR עכו)`
- **ar**: `(حيفا OR عكا OR "كريات شمونة" OR نهاريا OR صفد OR "كريات بيالك" OR الجليل OR الجولان OR شفاعمرو)`
- **ru**: `("Кирьят-Шмона" OR Хайфа OR Нагария OR "Кирьят-Бялик" OR Цфат OR Галилея OR Голаны OR Акко)`
- **en**: `("Kiryat Shmona" OR "Kiryat Bialik" OR Haifa OR Naharia OR Acre OR "Upper Galilee" OR Galilee OR Golan OR Metula)`

If the topic has no reasonable translation into a language, **omit that language** and record the omission in the report.

If a constructed query exceeds 512 chars, **trim the topic-term list first** — never the locality list.

**Before any X spend, print the constructed queries** (one per language) so the user can sanity-check the vocabulary. If queries look wrong, stop — the user can rerun with a clearer topic.

## Step 1 — Dry-run cost estimate (ALWAYS runs first)

For each (date × language) slot, call `counts/recent`. Clamp `end_time` to `now-60s` when the slot day is today UTC (X rejects future `end_time`):

```
QE=$(printf '%s' "$Q" | jq -sRr @uri)
if [ "$DATE" = "$(date -u +%F)" ]; then END=$(date -u -d '60 seconds ago' +%FT%TZ); else END="${DATE}T23:59:59Z"; fi
curl -s -G "https://api.x.com/2/tweets/counts/recent" \
  --data "query=$QE" \
  --data "start_time=${DATE}T00:00:00Z" \
  --data "end_time=${END}" \
  --data "granularity=day" \
  -H "Authorization: Bearer $X_BEARER_TOKEN"
```

Each call = **$0.005**. Append one line to the spend log per call:
```
{"ts":"...","endpoint":"counts/recent","date":"...","lang":"...","result_count":N,"est_cost_usd":0.005}
```

Aggregate via jq (don't iterate yourself):
```
jq -s '
  map(select(.endpoint=="counts/recent")) as $rows |
  {
    counts_calls: ($rows|length),
    total_counts_cost: ($rows | map(.est_cost_usd) | add),
    by_date: ($rows | group_by(.date) | map({date:.[0].date, total:(map(.result_count)|add)})),
    by_lang: ($rows | group_by(.lang) | map({lang:.[0].lang, total:(map(.result_count)|add)})),
    grand_total_posts_projected: ($rows | map(.result_count)|add),
    capped_per_call: ($rows | map(if .result_count > '"$MAXPQ"' then '"$MAXPQ"' else .result_count end) | add),
    est_post_cost: (($rows | map(if .result_count > '"$MAXPQ"' then '"$MAXPQ"' else .result_count end) | add) * 0.005)
  }
' "$SPEND_LOG"
```

Compute projection:
- `est_total_x = total_counts_cost + est_post_cost`
- If `--with-replies`: `est_total_x += min(20, min(60, candidates)) × 50 × 0.005`

Abort if `est_total_x > --max-cost-usd` — print the number and suggest lowering `--max-per-query`.

Print one compact table (≤slots rows × 4 cols: date, lang, projected, capped) and a totals row.

**If `--execute` not passed:** print `Dry-run complete. Spent $<x> on counts/recent. Pass --execute --max-cost-usd <Y> to fetch posts.` and STOP. Do not run Steps 2+.

## Step 3 — Bash pre-filter → slim candidates file

Standard citizen-voice rejection rules (topic-agnostic): drop news handles, business/government verified accounts, and accounts whose bio identifies them as journalists/spokespersons/officials. For each raw file:

```
jq -c --arg date "$DATE" --arg lang "$LANG" '
  . as $root |
  (.includes.users // []) as $users |
  (.data // [])[] |
  . as $tweet |
  ($users[] | select(.id == $tweet.author_id)) as $u |
  select(
    ($tweet.text | gsub("https?://[^ ]+";"") | gsub("@[A-Za-z0-9_]+";"") | length) >= 12
    and ( ($u.username // "") | test("news|n12|kan|maariv|ynet|walla|mako|jpost|haaretz|globes|calcalist|israelhayom|kikar|srugim|themarker|davar|i24|reshet|reuters|afp|aljazeera"; "i") | not )
    and ( ($u.verified_type // "") | test("business|government"; "i") | not )
    and ( ($u.description // "") | test("journalist|כתב|כתבת|עיתונאי|reporter|correspondent|spokesperson|דובר|דוברת|פיקוד|idf|רשות|משרד|news|editor|anchor|host|presenter"; "i") | not )
  ) |
  {
    tid: $tweet.id, date: $date, lang: $lang, text: $tweet.text,
    created_at: $tweet.created_at, conv: $tweet.conversation_id,
    likes: ($tweet.public_metrics.like_count // 0),
    replies: ($tweet.public_metrics.reply_count // 0),
    quotes: ($tweet.public_metrics.quote_count // 0),
    handle: ($u.username // ""), user_name: ($u.name // ""),
    bio: (($u.description // "") | .[0:140]),
    user_loc: ($u.location // ""),
    followers: ($u.public_metrics.followers_count // 0),
    verified: ($u.verified // false),
    url: ("https://x.com/" + ($u.username // "i") + "/status/" + $tweet.id)
  }
' business_modules/social_media/data/x-raw-${DATE}-${LANG}-${SLUG}.json \
  >> business_modules/social_media/data/x-candidates-${TARGET}-${SLUG}.jsonl
```

Then top-60 by engagement:
```
jq -s 'sort_by(-(.replies + .likes + .quotes))[0:60]' \
  business_modules/social_media/data/x-candidates-${TARGET}-${SLUG}.jsonl \
  > business_modules/social_media/data/x-candidates-${TARGET}-${SLUG}.top60.json
```

Print one summary line: `Filtered <N_in> candidates → kept top 60 by engagement (<dropped> dropped by cap)`. Do not `Read` either file yet.

## Step 6 — Write or merge per-day topic-scoped bundles

For each of the 3 dates that has findings, write a new bundle and **merge** it into any existing same-slug bundle from a prior run on the same day. Slug-suffixed paths keep `/x-3` outputs separate from `/x-3-full`'s canonical bundle — there is no cross-command collision.

**6a.** Compose the new bundle in-context and `Write` it to a TEMP path: `business_modules/social_media/data/signals-social-<date>-<slug>.new.json`

Shape:
```json
{
  "date": "<date>",
  "topic": "<original topic string>",
  "topic_slug": "<slug>",
  "platforms_searched": ["x"],
  "gather_queries": {
    "he": "<query he>", "ar": "<query ar>", "ru": "<query ru>"
  },
  "window_days": 1,
  "extracted_at": "<now ISO>",
  "findings": [ /* this run's findings */ ],
  "verified_findings": <count where confidence != "נמוכה">,
  "low_confidence_findings": <count where confidence == "נמוכה">,
  "rejected": {
    "no_citizen_quote": <int>,
    "news_domain": <int>,
    "official_speaker": <int>,
    "off_topic": <int>
  },
  "rejected_examples": [ {"url":"...","reason":"..."} ]
}
```

Pull `rejected.*` counts from the bash pre-filter (Step 3 dropped-by-cap → `off_topic`) and from your Step 4 classification decisions.

**6b.** Merge with any pre-existing slug bundle from earlier same-day runs:

```bash
SLUG_BUNDLE="business_modules/social_media/data/signals-social-${DATE}-${SLUG}.json"
NEW_TEMP="business_modules/social_media/data/signals-social-${DATE}-${SLUG}.new.json"
if [ -f "$SLUG_BUNDLE" ]; then
  jq -s '
    .[0] as $old | .[1] as $new |
    (($old.findings // []) + ($new.findings // []) | unique_by(.id)) as $merged |
    $new + {
      findings: $merged,
      verified_findings: ($merged | map(select((.confidence // "") | tostring | test("נמוכה") | not)) | length),
      low_confidence_findings: ($merged | map(select((.confidence // "") | tostring | test("נמוכה"))) | length),
      rejected: {
        no_citizen_quote: (($old.rejected.no_citizen_quote // 0) + ($new.rejected.no_citizen_quote // 0)),
        news_domain: (($old.rejected.news_domain // 0) + ($new.rejected.news_domain // 0)),
        official_speaker: (($old.rejected.official_speaker // 0) + ($new.rejected.official_speaker // 0)),
        off_topic: (($old.rejected.off_topic // 0) + ($new.rejected.off_topic // 0))
      },
      rejected_examples: ((($old.rejected_examples // []) + ($new.rejected_examples // [])) | unique_by(.url))
    }
  ' "$SLUG_BUNDLE" "$NEW_TEMP" > "${SLUG_BUNDLE}.merged" && mv "${SLUG_BUNDLE}.merged" "$SLUG_BUNDLE"
  rm "$NEW_TEMP"
  echo "Merged into existing bundle: $SLUG_BUNDLE"
else
  mv "$NEW_TEMP" "$SLUG_BUNDLE"
  echo "Wrote new bundle: $SLUG_BUNDLE"
fi
```

The merge dedupes `findings` by `id` (each tweet appears once even if hit in multiple runs); `rejected.*` counters and `rejected_examples` accumulate; the new run's `extracted_at`, `topic`, `gather_queries`, and `platforms_searched` overwrite the old (the latest run owns the metadata).

## Safety invariants — DO NOT VIOLATE

- Never call `search/recent` or `search/all` without `--execute`.
- Never paginate beyond one page per query.
- Never request `max_results > 100`.
- Never proceed if the pre-flight X cost estimate exceeds `--max-cost-usd`.
- Never write the `X_BEARER_TOKEN` value to any file, log, or terminal output.
- Refuse to run if `<topic>` is empty, the system clock is in the future, or the target date is in the future.
- If any curl returns a non-2xx HTTP status, log the call as failed, abort, print the status code and X's `errors[]` payload.
- Never `Read` any `x-raw-*.json` file. Use jq summaries only.
- Never read the spend log in full — always aggregate via jq.
- Never spawn agents from inside this command (single-context-pass only).
- Never re-read a file you just wrote.
